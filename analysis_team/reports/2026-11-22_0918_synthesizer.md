## 이번 회차 Top 3 개선 제안

**1. LSTM 재학습용 1분봉 수집을 증분(incremental) 방식으로 전환 — execution 제안**
`local/data_fetcher.py`의 `_fetch_one`(약 373~390행)은 재학습마다 90일치 전체를 새로 받아 캐시 CSV를 통째로 덮어쓴다(`df.to_csv(cache_path, index=False)`, 378행). 하루 10회 재학습 × 6코인이면 코인당 약 648페이지, 전체 약 3,900회 API 호출이 2시간24분마다 반복된다. 캐시 CSV의 마지막 `open_time` 이후분만 받아 기존 캐시에 병합·중복제거·90일 cutoff 하도록 바꾸면 API 호출량이 극적으로 줄고 트레이딩 로직은 전혀 건드리지 않는다. 효과 대비 구현 난이도가 가장 좋은 항목이라 1순위로 둔다. 단, 과거 데이터 사후정정에 대비해 하루 1회 정도는 전체 재수집으로 보정하는 안전장치를 병행해야 한다(execution 리포트 자체가 지적한 트레이드오프).

**2. Portfolio에 peak_value/최대낙폭(drawdown) 필드 추가 — risk 제안**
`local/portfolio.py`의 `Portfolio` 데이터클래스(103~114행)는 `pnl_pct()`만 노출하고 변동성·낙폭 지표가 없다. `peak_value_krw`, `max_drawdown_pct` 필드를 추가하고 `total_value_krw()`가 갱신되는 지점(main_loop.py 497행 부근)에서 `update_drawdown()`을 호출, `to_doc()`에 포함시키면 된다. 신규 필드는 `from_doc()`에서 기본값으로 자동 채워져 기존 저장 데이터와의 마이그레이션 리스크가 거의 없고, 저장량 증가도 미미하다. 코드 변경 자체가 작고 리스크가 낮으면서, 지금까지 안 보이던 "전략별 실제 위험 수준"을 드러내 다른 개선(코인별 손절선 분리 등)의 판단 근거가 된다는 점에서 2순위.

**3. LSTM `finetune_chain_length` 전체 재학습 트리거 연결 — lstm 제안**
`lstm_model.py`가 `finetune_chain_length`를 `meta.json`에 이미 기록(236~266행)하고 있지만, `main_loop.py`의 `retrain_lstm()`에서 이 값으로 분기하는 로직이 없어 "깔아둔 안전장치가 쓰이지 않는" 상태다. `retrain_lstm()` 안에 `if get_finetune_chain_length(coin) >= 30: train_model(..., finetune=False)` 한 줄짜리 분기만 추가하면 되는 매우 낮은 구현 난이도 대비, 파인튠 연쇄로 인한 모델 드리프트를 막는 효과가 분명하다. 3순위.

(참고: strategy의 거래량 필터·trend_follow 윈도우 축소, lstm의 코인 간 상관 피처 추가도 타당하지만 전략 신호 자체를 바꾸는 작업이라 백테스트 검증이 선행되어야 해 "지금 바로" 항목에서는 보류.)

## 역할 간 의견 충돌 (있다면)
5개 리포트 사이에 직접적인 충돌(예: "매매를 늘려라" vs "줄여라")은 없었다. 다만 strategy 리포트 내부에 약한 긴장이 있다: 거래량 필터 추가(228~232, 372~375행)는 거래를 보수적으로 줄이는 방향이고, `trend_follow`의 `ma_window`/`buffer_pct` 축소 검토(349~350행)는 민감도를 높여 거래를 늘리는 방향이다. 두 제안 모두 strategy 분석가 자신이 "백테스트 필요", "휩쏘 위험 증가"라고 명시했으므로, 근거의 탄탄함은 거래량 필터(저유동성 구간 오작동 방지라는 명확한 실패 시나리오가 있음) 쪽이 더 높다. 윈도우 축소는 효과가 추정 수준이라 먼저 단독으로 백테스트해보고 거래량 필터와 동시에 넣지 않는 것이 안전하다.

## 전체 총평 (한 문단)
이번 회차는 치명적 버그보다 "이미 짜여 있지만 아직 연결·활용되지 않은 기능"(LSTM 재학습 트리거, 코인 상관 피처)과 "비용·가시성" 문제(API 호출 과다, 낙폭 지표 부재)가 중심이었고, storage 영역은 이미 성숙해 추가조치가 불필요하다는 보고가 나올 만큼 전반적으로 시스템이 안정화 단계에 들어섰다. 반대로 전략 신호 자체를 바꾸는 제안(거래량 필터, 파라미터 조정, 코인별 손절선 분리)들은 모두 제안자 스스로 백테스트·실데이터 확인을 전제로 달았으므로, 이번 Top 3는 신호 로직을 건드리지 않고 운영 비용과 관측 가능성을 높이는 저위험·저난이도 항목으로 구성했다.
