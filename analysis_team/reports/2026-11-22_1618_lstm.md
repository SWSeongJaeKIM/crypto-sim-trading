## 한줄 요약
`signal_with_confidence()`의 부호 버그는 올바르게 수정되었고 전반적 구조(피처/파인튠/롤백 안전장치)는 탄탄하나, confidence 공식이 임계값 대칭성에 암묵적으로 의존하는 점과 피처에 타코인(특히 BTC) 상관 신호가 빠진 점이 남은 개선 여지다.

## 발견한 점 (우선순위 순)

**1. (검증) confidence 수정은 맞지만 "대칭 임계값" 가정에 암묵적으로 의존 (중요도: 중)**
`lstm_model.py:429-431`에서 `threshold_distance = PROB_BUY_MIN - 0.5`만 계산해 BUY/SELL 양쪽 confidence 정규화에 공통으로 쓴다. 현재 `PROB_BUY_MIN=0.60`, `PROB_SELL_MAX=0.40`으로 정확히 대칭(`0.60-0.5 == 0.5-0.40`)이라 지금은 수치가 맞다(검증: prob_up=0.60→0, 1.0→1.0, 0.40→0, 0.0→1.0, 모두 정상). 하지만 이 파일 상단 주석(L58-61)에 "기존 0.55/0.45 → 0.60/0.40으로 튜닝"한 전례가 있어, 향후 BUY/SELL 임계값을 비대칭으로 재튜닝하면 SELL 쪽 confidence가 조용히 틀어진다. 버그는 아니고 "함정이 될 수 있는 암묵 가정"이다.

**2. FEATURE_COLS에 코인 간 상관 신호 부재 (중요도: 중)**
`FEATURE_COLS`(L71) 5개 모두 해당 코인 자신의 지표(ret, vol_chg, rsi, macd, bb_pctb)뿐이다. 알트코인 1분 방향은 BTC 움직임에 상당 부분 종속되는 경우가 흔한데, BTC 대비 상대 강도나 BTC ret 같은 cross-asset 피처가 없다. 호가 스프레드는 Upbit 1분봉 OHLCV만 쓰는 이 구조상 애초에 입력 데이터에 없을 가능성이 높아(이 파일만으로는 데이터 소스 확인 불가 — main_loop.py의 데이터 로딩부를 봐야 판단 가능), 스프레드보다는 BTC 상관 피처 추가가 더 현실적인 개선 지점이다.

**3. finetune_chain_length 추적만 하고 자동 액션 없음 (중요도: 낮음, 이미 알려진 open 이슈)**
`get_finetune_chain_length()`(L319-337)와 L271-275의 체인 길이 기록은 "영구 이어학습" 구조에서 레짐 고착을 감지하기 위한 관측값일 뿐, 이 파일 안에 그 값을 보고 자동으로 `finetune=False` 전체 재학습을 트리거하는 로직은 없다(주석 L247-251, L319-329에 이미 명시된 known gap). 호출부(main_loop.py)가 이 값을 실제로 쓰는지는 이 파일만으로 확인 불가.

(참고: 질문 전제인 "재학습 주기 하루 1회 + 30일 학습 기간"은 이 파일 자체의 docstring(L17-21)이 기술하는 실제 값("하루 10회, 약 2시간24분 간격, HISTORY_DAYS_FOR_TRAIN=90일")과 다르다. 정확한 운영값은 main_loop.py를 봐야 확정되므로 이 파일만으로는 "하루 1회/30일" 전제로 판단할 수 없다.)

## 구체적 제안
- `lstm_model.py:429-431`: SELL 쪽 threshold를 분리.
  ```python
  threshold_distance = (PROB_BUY_MIN - 0.5) if sig == "BUY" else (0.5 - PROB_SELL_MAX)
  confidence = (distance_from_mid - threshold_distance) / (0.5 - threshold_distance)
  ```
  지금은 결과값이 동일하므로 회귀 없는 방어적 리팩터링.
- `FEATURE_COLS`(L71) 확장 검토: `build_features(df, btc_close: pd.Series | None = None)` 형태로 BTC close 시리즈를 받아 `btc_ret`, `rel_strength = ret - btc_ret` 피처 추가. main_loop.py가 코인별 df를 어떻게 들고 있는지 확인이 선행 필요.
- `main_loop.py`(이 파일 밖) 쪽에서 `get_finetune_chain_length(coin)`이 실제 임계치 비교 후 `train_model(..., finetune=False)` 호출로 이어지는지 확인 — 없다면 그쪽에 연결 로직 추가.

## 리스크/트레이드오프
- confidence 분리 계산은 코드 복잡도만 소폭 증가, 수치 회귀는 없음.
- BTC 상관 피처 추가는 입력 차원 증가로 적은 샘플 상황에서 과적합 위험이 소폭 커지고, BTC 데이터 결측 시 전체 코인 추론이 영향받는 새로운 의존성이 생긴다.
- finetune_chain_length 자동 트리거는 전체 재학습(처음부터) 시간이 길어져 하루 10회 스케줄의 하트비트 간격에 영향을 줄 수 있고, 리셋 직후 모델은 `VAL_ACC_ROLLBACK_THRESHOLD`와 상호작용해 일시적으로 저장이 계속 스킵될 수 있어 함께 검증 필요.
