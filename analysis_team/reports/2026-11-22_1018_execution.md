## 한줄 요약
예외처리·API 호출 패턴·사이클 타이밍 보정은 이미 여러 차례의 분석 라운드를 거쳐 상당히 견고하게 구현되어 있으며, 남은 갭은 "데이터 부족 스킵"에 대한 로깅 누락과 429 응답 시 Retry-After 미반영 정도의 경미한 수준이다.

## 발견한 점 (우선순위 순)

**1. 캔들 부족으로 신호 계산이 스킵될 때 로그가 전혀 없음**
`main_loop.py` 423~425행:
```python
if len(df) < strat.min_bars():
    continue
```
모델 파일 없음(442행 근처)이나 가격 데이터 없음(365~376행 근처)은 코인별 1시간 쓰로틀 경고가 있는데, 이 조건만 아무 로그 없이 조용히 스킵된다. 신규 코인 추가, `min_bars()` 요구치 증가, 혹은 `count` 파라미터 변경 등으로 특정 코인이 영구히 신호 계산에서 빠져도 사후에 run.log로는 전혀 알 수 없다.

**2. `_http_get_json`이 HTTP 429 응답의 `Retry-After` 헤더를 읽지 않음**
`data_fetcher.py` 108~152행, 특히 150~151행:
```python
if attempt < retries - 1:
    time.sleep(1.0 * (attempt + 1))
```
429(rate limit)로 재시도할 때도 무조건 고정 백오프(1초, 2초)만 쓴다. Upbit이 `Retry-After`를 보내는 경우 이를 무시하면 서버가 요구하는 시간보다 일찍 재시도해 추가로 429를 받을 가능성이 있다.

**3. 나머지(예외처리 격리, 재학습 블로킹 로깅, 사이클 드리프트 보정, 로그 회전/쓰로틀)는 이미 잘 되어 있음**
전략/코인 단위 예외 격리, FileNotFoundError 전용 처리, 반복 예외 1시간 쓰로틀, 사이클 경과시간 기반 sleep 보정(60초 드리프트 방지), RotatingFileHandler, 증분 데이터 수집과 전역 RateLimiter 공유, 멈춘 페이지네이션 감지(stuck_count) 등은 각 코드 블록에 구체적 분석 리포트 근거까지 남겨 이미 다뤄졌다. 억지로 추가 문제를 만들 필요가 없는 영역이다.

## 구체적 제안

- **(1) 관련**: `main_loop.py`에 `_warned_missing_model`과 같은 패턴으로 `_warned_insufficient_bars: set[tuple[str, str]] = set()` 전역 세트를 추가하고, 423행의 `continue` 직전에 `(strat_name, coin)`이 세트에 없을 때만 `log.warning(f"[{strat_name}/{coin}] 캔들 부족(len={len(df)} < min_bars={strat.min_bars()}) — 신호 계산 스킵")`을 남기고 세트에 추가한다.
- **(2) 관련**: `data_fetcher.py` 150~151행을 수정해, `isinstance(e, urllib.error.HTTPError) and e.code == 429`이고 `e.headers.get("Retry-After")`가 있으면 `float()` 파싱 후 그 값만큼(단, 과도한 지연 방지를 위해 상한 예: `min(value, 5)`초) sleep하고, 없거나 파싱 실패 시 기존 `1.0 * (attempt + 1)` 백오프로 폴백한다.

## 리스크/트레이드오프 (제안을 적용하면 생길 수 있는 부작용)

- (1) 적용 시: 세트 기반 1회성 경고라서 `_warned_missing_model`과 동일하게, 문제가 실제로 해결됐는지(캔들이 다시 충분해졌는지)는 로그만으로 재확인이 어렵다. 다만 코인 수가 적어(6개) 메모리 누적 우려는 없다.
- (2) 적용 시: `Retry-After` 값에 상한을 두지 않으면 60초 주기로 호출되는 `fetch_latest_minute_candles`(timeout=5, retries=2) 경로에서 지연이 `CYCLE_ELAPSED_WARN_THRESHOLD_SEC`(30초)를 넘길 위험이 있어, 반드시 짧은 상한(예: 5초)을 함께 둬야 한다. 또한 비표준 헤더 형식에 대한 예외처리 코드가 추가되어 함수 복잡도가 약간 늘어난다.

(검토 대상 파일: local/main_loop.py, local/data_fetcher.py. 실제 운영 데이터는 확인하지 않았으며, 코드 구조와 로직만으로 판단한 결과입니다.)
