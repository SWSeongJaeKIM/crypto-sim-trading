## 한줄 요약
숏 레버리지 배팅 비율 로직과 코인 간 동일 리스크 배분 두 곳에서 실질적인 리스크 불균형이 남아 있다(물타기형 손절 문제는 `first_entry_price_krw`로 이미 잘 해소됨).

## 발견한 점 (우선순위 순)

**1. 숏 포지션 사이징이 레버리지를 무시해 롱보다 손절 1회당 손실이 3배 크다.**
`portfolio.py` `apply_sell_signal`(279행)이 `open_short`에 넘기는 `fraction`은 `confidence_to_trade_fraction`(main_loop.py 357행)이 만든 0.1~0.9 비율이며, 롱의 `buy()`와 완전히 같은 스케일이다. 그런데 `open_short`(196~200행)은 이 비율을 "마진" 비율로 쓰고 `notional = margin * LEVERAGE`(200행)로 3배를 키운다. 결과: 같은 확신도 0.9로 롱을 열면 손절(8%) 시 손실 = 코인 자금의 7.2%(0.9×8%)지만, 숏을 열면 손실 = 코인 자금의 21.6%(0.9×LEVERAGE×8%, 221행 로그 주석의 "실제 마진 손실률 STOP_LOSS_PCT×LEVERAGE=24%"와 일치)다. 즉 SELL 신호 쪽이 BUY 신호보다 같은 확신도에서 약 3배 더 공격적인 리스크를 지는데, 이는 설계 의도가 아니라 사이징 함수를 레버리지 없이 그대로 재사용한 결과로 보인다.

**2. BTC와 DOGE에 동일 배분·동일 레버리지·동일 손절%을 적용 — 과거에 지적된 문제가 아직 코드에 남아 있다.**
`portfolio.py` 46행 `COINS` 6개가 130행 `per_coin = initial_capital_krw / len(coins)`로 균등 배분되고, 53~54행 `LEVERAGE`/`STOP_LOSS_PCT`는 코인 구분 없는 전역 상수다. `check_stop_loss_and_liquidation`(308행, 321행)도 이 전역 값만 참조한다. `storage.py`의 `stop_loss_counts_by_coin`과 `dashboard.py` 228행 주석을 보면 "변동성 큰 코인이 더 자주 손절에 걸리는지"를 집계는 하지만 "이 집계만으로 손절선/배분을 바로 바꾸지는 않음"이라고 명시돼 있어, 모니터링만 있고 실제 완화 로직은 아직 반영되지 않은 상태다. (실제로 DOGE가 BTC보다 몇 배 더 자주 손절에 걸리는지는 운영 DB를 봐야 확인 가능 — 코드만으로는 "구조적으로 가능성이 있다"까지만 판단된다.)

**3. (참고, 문제는 아님) 손절/강제청산 안전마진, 물타기 방지, 드로다운 추적은 이미 잘 설계돼 있다.** `first_entry_price_krw`로 손절선이 평단가 이동에 영향받지 않게 고정됐고, `STOP_LOSS_PCT(8%) < LIQUIDATION_PCT(33.3%)` 여유도 충분하며, `peak_value_krw`/`max_drawdown_pct`가 이미 추가돼 단순 수익률 외 리스크 지표도 확보돼 있다.

## 구체적 제안
- `portfolio.py` 279행: `self.open_short(coin, price_krw, pct_of_cash=fraction, ...)` → `pct_of_cash=fraction / LEVERAGE`로 변경. 이렇게 하면 `notional = margin*LEVERAGE = cash*fraction`이 되어 같은 확신도에서 롱/숏의 자금 노출(notional)이 같아진다.
- `portfolio.py` 53~54행 전역 `LEVERAGE`, `STOP_LOSS_PCT`를 코인별 딕셔너리(예: `COIN_STOP_LOSS_PCT = {"BTC": 0.06, ..., "DOGE": 0.10}`)로 바꾸고, 308행·321행에서 `STOP_LOSS_PCT` 대신 `COIN_STOP_LOSS_PCT.get(coin, STOP_LOSS_PCT)`를 참조하도록 수정. 값 산정은 `storage.py`의 기존 `stop_loss_counts_by_coin` 집계 데이터를 활용.

## 리스크/트레이드오프
- 제안 1을 적용하면 숏 포지션 크기가 약 1/3로 줄어 숏 전략의 절대 수익/손실 규모가 작아지고, 기존 누적 포트폴리오와 롱·숏 비중 비교 시 과거 데이터와 불연속이 생긴다.
- 제안 2는 코인별 상수 관리가 늘어나 테스트/재조정 부담이 커지고, 값을 잘못 잡으면(예: DOGE 손절을 너무 넓게 두면) 오히려 손실이 커질 수 있어 운영 데이터 기반 튜닝이 필수다.

검토 대상 파일: local/portfolio.py (전체), local/main_loop.py (357~363행, 507~539행 매매 실행부). 코드를 수정하지 않았음 — 리뷰/분석만 수행.
