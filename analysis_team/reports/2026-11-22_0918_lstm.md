## 한줄 요약
LSTM 모듈 자체는 이전 리뷰(VAL_ACC_ROLLBACK_THRESHOLD, finetune_chain_length, SEQ_LEN 정합성 수정 등)를 이미 반영해 안정적인 구조이며, 지금 당장 바꿔야 할 치명적 결함은 없음 — 남은 개선 여지는 "피처 확장"과 "이미 깔아둔 메타데이터(finetune_chain_length)를 실제로 쓰는 전체 재학습 트리거 연결" 두 가지로 좁혀진다.

## 발견한 점 (2~4개, 우선순위 순)

1. **FEATURE_COLS(lstm_model.py 71행)가 모두 "해당 코인 자체" 파생 지표뿐** — ret/vol_chg/rsi14/macd_hist/bb_pctb는 조건식 전략들이 쓰는 지표와 동일 소스라, 모델이 조건식보다 더 많은 정보를 보는 게 아니라 같은 정보를 비선형으로 재조합하는 수준이다. 다른 코인(예: BTC)과의 상관관계 피처는 전혀 없음. 반면 호가 스프레드는 data_fetcher.py에 orderbook 수집 코드 자체가 없어 지금은 추가 불가능(새 API 연동이 먼저 필요).

2. **다른 코인 상관 피처는 데이터상 바로 추가 가능** — main_loop.py의 retrain_lstm()이 이미 `fetch_all_minute_history()`로 6개 코인 전체를 한 번에 받아오므로(main_loop.py 544행), 코인별 train_model 호출 시 기준 코인(BTC 등)의 ret을 같은 타임스탬프로 merge해서 넘기는 건 인프라 추가 없이 가능한 변경이다.

3. **finetune_chain_length가 기록만 되고 아직 쓰이지 않음** — lstm_model.py 236~266행에서 연속 파인튠 횟수를 meta.json에 쌓아두고, get_finetune_chain_length() 헬퍼(310행)까지 만들어 조회 가능하지만, main_loop.py의 retrain_lstm() 쪽에서 이 값을 보고 "N회 이상이면 전체 재학습"으로 분기하는 로직은 아직 연결되지 않았다(주석에도 명시된 기존 known gap).

4. SEQ_LEN(60)·모델 크기(hidden=32, 1layer)와 데이터량(코인당 약 13만 샘플) 간 과적합/과소적합 소지는 코드만으로 보면 양호 — 모델이 작아 과적합 위험은 낮고, val_acc 54~62%라는 docstring 상의 수치(이는 실제 운영 데이터가 아니라 코드 주석에 설계 근거로 적힌 값)에 맞춰 임계값(0.60/0.40)을 이미 보수적으로 올려둔 점도 합리적 대응이다.

## 구체적 제안

- **lstm_model.py**: `build_features(df, ref_close: pd.Series | None = None)`로 시그니처를 확장하고, `ref_close`가 주어지면 `ref_ret = ref_close.pct_change()`를 FEATURE_COLS에 `"ref_ret"`로 추가(71행 리스트에 항목 1개 추가 + N_FEATURES 자동 반영). `build_dataset`/`predict_proba`에도 동일 인자를 통과시킨다.
- **main_loop.py 532행 부근 retrain_lstm()**: `fetch_all_minute_history()` 결과에서 BTC(또는 거래량 1위 코인) df를 꺼내 각 코인 train_model 호출 시 `ref_close=btc_df["close"]`로 넘긴다. BTC 자신을 학습할 때는 ref_close를 넘기지 않거나 0으로 채운다.
- **main_loop.py retrain_lstm() 안**: 코인별 호출 전에 `if lstm_model.get_finetune_chain_length(coin) >= 30:`(하루 10회 기준 약 3일치) 조건으로 `train_model(..., finetune=False)`를 강제하는 분기 1줄 추가. 학습 로직은 그대로 두고 호출부만 연결하면 된다.

## 리스크/트레이드오프

- 상관 피처 추가 시 기준 코인 데이터 결측/실패가 전체 ret=0으로 채워져("변화 없음"으로 학습) 오히려 노이즈가 될 수 있다 — merge 실패 시 해당 피처를 통째로 생략하는 가드가 필요하다.
- finetune_chain_length 임계치로 전체 재학습을 트리거하면, 그 순간 lr이 3배로 커지고 가중치가 초기화되어 일시적으로 신호가 급변하거나 val_acc가 떨어질 수 있다(다만 VAL_ACC_ROLLBACK_THRESHOLD 안전망이 큰 하락은 걸러줌).
- 이 변경들이 실제 손익/적중률을 개선하는지는 실제 운영 데이터(거래내역, val_acc 추이)를 봐야 판단 가능 — 이번 리뷰는 코드 구조만으로 판단한 것이라 효과를 보장하지 않는다.

참고로, 프롬프트가 가정한 "재학습 주기 하루 1회 + 학습 데이터 30일"은 현재 코드와 다르다 — main_loop.py 기준 실제로는 하루 10회(약 2시간24분 간격), HISTORY_DAYS_FOR_TRAIN=90일(과거 30일에서 GPU 사용으로 확대됨)이다. 이 질문에 대한 답은 현재 코드 기준으로 위 발견 3, 4번에 반영했다.
