## 한줄 요약
두 파일은 이미 여러 차례의 자체 분석팀 리포트를 거쳐 예외처리·로깅·사이클 드리프트 보정이 상당히 촘촘하게 구현되어 있다. 코인/전략 단위 격리, 반복 예외 쓰로틀링, elapsed-time 기반 60초 보정, 로그 회전까지 모두 되어 있어 해당 영역은 추가로 손댈 필요가 없다. 남은 실질적 개선 포인트는 LSTM 재학습 시 90일치 1분봉을 매번 전량 재수집하는 pagination 비효율 한 가지가 가장 크다.

## 발견한 점 (2~4개, 우선순위 순)

1. **(가장 중요) 재학습마다 90일치 전체를 매번 재수집한다** — `data_fetcher.py` `fetch_all_minute_history`/`_fetch_one`(373~390행)과 `fetch_minute_history`(184~286행). 캐시 CSV(`DATA_DIR/{coin}_1m_{days}d.csv`)는 fetch 자체가 실패했을 때의 폴백으로만 읽히고(388~390행), 성공 시엔 항상 덮어쓰기만 한다. `main_loop.py`의 `RETRAIN_TIMES_LOCAL`이 하루 10회이므로, 코인당 약 648페이지(90일×1440/200) × 6코인 ≈ 3,900회의 Upbit 호출이 2시간24분마다 반복된다. 직전 슬롯과 겹치는 데이터(거의 전부)까지 매번 새로 받아오는 구조라, 불필요한 API 호출/시간 소모가 반복적으로 누적된다.

2. **(경미) `_http_get_json`의 재시도가 HTTP 상태코드를 구분하지 않는다** — `data_fetcher.py` 108~141행. `urllib.error.HTTPError`를 네트워크성 예외와 동일하게 취급해, 영구적인 4xx(예: 마켓 코드 오타, API 스펙 변경)도 3회(백오프 1+2초 포함)까지 재시도한 뒤에야 실패한다. 매 60초 사이클마다 호출되는 `fetch_latest_minute_candles`에서 이런 상황이 생기면 사이클 지연에 조금씩 기여할 수 있다. 다만 마켓 코드가 고정값이라 실제 발생 확률은 낮다.

3. **예외처리/사이클 타이밍/로깅은 이미 충분하다** — 전략·코인 단위 try/except 격리, 반복 예외 1시간 쓰로틀, 모델 파일 없음 최초 1회 경고, elapsed 기반 sleep 보정(재학습 시간 포함), 30초 임계치 경고, RotatingFileHandler 등 요청된 리뷰 항목 대부분이 이미 구현·검증되어 있다. 억지로 추가 문제를 만들 필요는 없어 보인다.

## 구체적 제안

- **data_fetcher.py `_fetch_one`(약 373~390행)**: 기존 캐시 CSV가 있으면 `pd.read_csv`로 읽어 마지막 `open_time`을 구하고, `fetch_minute_history`를 그 시점 이후분만 받도록 호출(예: `days` 대신 "마지막 캐시 시점 ~ 지금" 구간만 pagination)한 뒤, `pd.concat([cached_df, new_df]).drop_duplicates(subset="open_time").sort_values("open_time")`로 병합, 90일 cutoff로 다시 잘라서 저장. `fetch_minute_history`에 `since: pd.Timestamp | None` 파라미터를 추가해 `cutoff` 계산 기준을 바꾸는 정도로 구현 가능.
- **data_fetcher.py `_http_get_json`(108~141행)**: `except urllib.error.HTTPError as e:` 분기를 분리해, `e.code`가 429 또는 5xx일 때만 재시도, 그 외 4xx는 즉시 `raise FetchError`로 전환.

## 리스크/트레이드오프

- 증분 수집 도입 시 머지/정렬/중복제거 로직이 추가되어 복잡도가 약간 올라가고, 캐시 파일이 손상되거나 Upbit 쪽에서 과거 데이터를 사후 정정하는 경우 오래된 캐시 값이 그대로 섞여 들어갈 위험이 있다 — 하루 1회 정도는 전체 재수집으로 캐시를 통째로 갱신하는 보정 로직을 같이 두는 것이 안전하다.
- 4xx 즉시 실패 처리로 바꾸면, Upbit이 드물게 일시적으로 4xx를 반환하는 경우(문서화되지 않은 엣지케이스) 기존엔 재시도로 복구되던 것이 즉시 실패로 바뀔 수 있다. 다만 마켓 코드가 고정값이라 실제 영향은 제한적이다.

(참고: 분석은 코드 구조/로직만 기준으로 했으며, 실제 운영 중인 거래내역/손익/재학습 정확도 추이 등은 보지 않았음 — 그 부분은 실제 운영 데이터를 봐야 판단 가능함.)
