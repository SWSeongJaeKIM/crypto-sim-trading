## 한줄 요약
피처/모델 구조는 데이터 특성(낮은 신호 대 잡음비)에 맞게 보수적으로 설계되어 있고 롤백 안전장치도 갖췄으나, "영구 파인튠 체인"의 자동 리셋 정책 부재와 코인 자신 외 외부 피처 부재가 남은 공백이다.

## 발견한 점 (우선순위 순)
1. `finetune_chain_length`가 meta.json에 기록되지만(249, 266, 276-279행) 정책적으로 소비되지 않음 — 몇 회 연속 파인튠됐는지 추적만 하고, 임계치를 넘으면 전체 재학습(finetune=False)을 트리거하는 로직이 없음. 이 공백은 코드 주석(240-243, 318-320행)에서 팀도 이미 인지한 상태. "영구 이어학습" 구조상 체인이 무한정 길어지면 가중치가 과거 레짐에 고착(stale)될 위험이 남아 있음.
2. `FEATURE_COLS`(71행)는 해당 코인 자신의 OHLCV 파생 지표 5개(ret, vol_chg, rsi14, macd_hist, bb_pctb)뿐 — 호가 스프레드, 다른 코인(특히 BTC) 수익률 같은 시장 공통 피처가 없음. 암호화폐는 코인 간 동조화가 강해 BTC 방향이 알트코인 단기 방향에 선행 정보가 될 수 있는데, 이 신호를 모델이 전혀 보지 못함.
3. 질문에 제시된 "하루 1회, 30일" 가정은 실제 코드(18-19행 docstring)와 다름 — 현재 코드는 하루 10회(약 2시간24분 간격), HISTORY_DAYS_FOR_TRAIN=90일 윈도우. 윈도우가 거의 겹쳐 신규 데이터 비중이 구조적으로 작다는 점은 이미 인지하고 `finetune_lr = lr/3`(151-158, 198행)으로 완화 중 — 적절한 대응으로 판단됨.
4. `SEQ_LEN=60`, `LSTMClassifier`(hidden=32, 1층, head 32→16→1)는 코인당 수만~13만 샘플(42행 주석) 대비 작은 모델이라 과적합 소지는 낮고, val_accuracy 기반 롤백 안전장치(254-260행)까지 있어 구조 자체는 이미 균형이 잘 잡혀 있음. 추가로 복잡하게 만들 필요는 보이지 않음.

## 구체적 제안
- (발견 1) 69행 부근에 `FINETUNE_CHAIN_RESET_THRESHOLD = 30` 같은 상수를 추가하고, train_model() 내부 266행 이후에서 `if resumed_from_existing and prev_chain_length >= FINETUNE_CHAIN_RESET_THRESHOLD:` 조건이 참이면 반환 dict에 `"needs_full_retrain": True` 같은 플래그를 담아, 호출부(main_loop.py의 retrain_lstm())가 다음 호출을 `finetune=False`로 실행하도록 한다. 이 파일 안에서 정책의 "신호"는 만들 수 있지만 실제 적용은 main_loop.py와 함께 설계해야 함.
- (발견 2) `build_features(df, market_df=None)`처럼 시그니처를 확장해 BTC 1분 수익률을 추가 피처로 넣는 것을 검토. 다만 build_dataset(98행)/train_model(141행)/predict_proba(353행)/LSTMStrategy.signal(379행) 전체 호출 체인에 market_df를 전달해야 해서 local/main_loop.py 쪽 변경과 함께 설계해야 하고, 이 파일 단독 패치로는 불가능.

## 리스크/트레이드오프 (제안을 적용하면 생길 수 있는 부작용)
- 체인 리셋 정책 추가 시, 리셋 직후(finetune=False) val_accuracy가 일시적으로 떨어질 수 있고, 리셋 주기를 너무 짧게 잡으면 "최근 패턴 반영"이라는 현재 구조의 장점을 스스로 깎아먹을 수 있음 — 임계값은 실제 운영 데이터로 튜닝 필요.
- BTC 수익률 피처 추가는 코인별 신호가 BTC 방향에 과도하게 동조하게 만들어, "조건식 4개 전략과 다양하게 경쟁"시키려는 설계 의도(4-6행)와 달리 LSTM 신호의 독립성이 줄어들 수 있음. 또한 입력 차원이 바뀌므로 기존 저장된 .pt 파일과 호환이 끊겨 전체 재학습이 필요함.
- 실제 운영 중 거래 건수/손익/정확도 추이는 로컬 PC의 실거래 데이터를 봐야 판단 가능 — 이 리포트는 코드 구조만으로 판단한 것임.
