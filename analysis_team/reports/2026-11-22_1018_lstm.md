## 한줄 요약
`lstm_model.py`의 파인튠 밸런스 로직(`finetune_lr`, `finetune_chain_length` 기반 강제 전체재학습)은 이미 구현·연동되어 적절하게 작동 중이며, 가장 의미 있는 개선 여지는 "피처가 전부 단일 코인 자체 파생 지표뿐"이라는 점 하나로 좁혀진다.

## 발견한 점 (우선순위 순)

1. **FEATURE_COLS(lstm_model.py:71)가 전부 해당 코인 자체 파생 지표** — `ret, vol_chg, rsi14, macd_hist, bb_pctb` 모두 조건식 전략(`strategies.py`)과 같은 소스다. 다른 코인(특히 BTC)과의 상관관계 피처가 전혀 없어, 알트코인이 BTC 급변에 선행/후행하는 패턴을 모델이 볼 수 없다. 호가 스프레드는 `data_fetcher.py`에 오더북 수집 자체가 없어 지금 당장은 추가가 불가능(별도 API 연동 필요)하므로, 실현 가능한 쪽은 BTC 상관 피처다.

2. **과제 전제("하루 1회+30일")가 실제 코드값과 다름** — `main_loop.py` 44~48행 기준 실제로는 `RETRAIN_TIMES_LOCAL` 하루 10회(약 2시간24분 간격), `HISTORY_DAYS_FOR_TRAIN=90`일이다(코드로 직접 확인함). 1분봉 방향 예측 과제 특성(빠른 레짐 변화 + 통계적 안정성 확보)을 감안하면 이 실제 값(10회/90일)은 무리한 조합으로 보이지 않는다.

3. **파인튠 "최근 반영 vs 과거 망각" 균형은 이미 잘 설계되어 있음** — `finetune_lr = lr/3`(lstm_model.py 151~158, 198행)로 급격한 덮어씌움을 막고, `main_loop.py` 84행 `FINETUNE_CHAIN_LENGTH_RESET_THRESHOLD=30` + 560~568행에서 연속 파인튠 30회(약 3일) 이상이면 `finetune=False`로 강제 전체 재학습을 트리거하는 구조가 이미 연결되어 있다. 여기에 더해 `VAL_ACC_ROLLBACK_THRESHOLD`(lstm_model.py 69행)로 성능 하락 시 저장 자체를 막는 안전망도 있어, 추가 수정이 필요한 부분은 보이지 않는다.

4. **SEQ_LEN(60)·모델 크기(hidden=32, 1layer)는 데이터량 대비 적절** — 코인당 약 13만 샘플에 비해 모델 파라미터 수가 작아 과적합 위험은 낮고, 오히려 라벨 자체(1분 방향)의 예측 난이도가 높아 val_acc가 54~62%(코드 주석상 수치)에 머무는 구조로 보인다. 이에 맞춰 임계값을 0.60/0.40으로 올려(lstm_model.py 60~61행) 저확신 구간 매매를 줄인 조치도 합리적이다.

## 구체적 제안
- `local/lstm_model.py` 75행 `build_features(df, ref_close: pd.Series | None = None)`로 시그니처 확장, `ref_close`가 있으면 `ref_ret = ref_close.pct_change()`를 71행 `FEATURE_COLS`에 추가. `build_dataset`(98행)과 `predict_proba`(353행)에도 `ref_close` 인자를 통과시켜 동일 타임스탬프로 정렬.
- `local/main_loop.py` `retrain_lstm()`(527행 부근, 특히 552행 코인 루프)에서 이미 받아온 `fetch_all_minute_history()` 결과 중 BTC df를 꺼내 각 코인 `train_model` 호출 시 `ref_close=btc_df["close"]`로 넘긴다. BTC 자신을 학습할 때는 생략.

## 리스크/트레이드오프 (제안을 적용하면 생길 수 있는 부작용)
- BTC 데이터 수집 실패/결측 시 `ref_ret`이 전부 0("변화 없음")으로 채워지면 오히려 잘못된 신호가 될 수 있어, merge 실패 시 해당 피처 자체를 생략하는 가드가 필요하다.
- 피처 추가는 입력 차원이 늘어나므로 미세하게 재학습 시간이 늘고, 기존 저장된 가중치(`N_FEATURES=5` 기준)와 호환되지 않아 최초 1회는 `finetune=False` 전체 재학습이 강제된다.
- 이 피처 추가가 실제 방향 적중률·손익을 개선하는지는 코드만으로 보장할 수 없고, 실제 운영 데이터(val_accuracy 추이, 거래 손익)를 봐야 판단 가능하다.
