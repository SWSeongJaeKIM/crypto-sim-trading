## 한줄 요약
전체 파이프라인(피처/모델 크기/파인튜닝/재학습 주기)은 데이터 규모 대비 합리적으로 설계되어 있으나, `build_dataset`의 윈도우-라벨 인덱싱이 1틱 어긋나 있어 학습과 추론이 서로 다른 시점을 예측하는 구조적 버그가 가장 시급한 문제입니다.

## 발견한 점 (우선순위 순)

1. **(최우선) 학습/추론 간 타깃 시점 불일치 (lstm_model.py 76~81행 vs 216행)**: `build_dataset`에서 윈도우는 `arr[i-seq_len:i]`(마지막 행 인덱스 `i-1`)이고 라벨은 `close[i+1]` vs `close[i]`의 변화입니다. 즉 윈도우 끝(`i-1`)과 예측 대상 구간(`i→i+1`) 사이에 1틱 공백이 있어, 모델은 사실상 "윈도우 끝+2" 시점의 변화를 학습합니다. 반면 `predict_proba`(216행)는 `feat[-seq_len:]`로 가장 최근 데이터까지 포함한 윈도우를 그대로 넣습니다. 학습 시의 인덱싱 규칙을 적용하면, 추론 시 실제로 예측되는 건 "다음 1분봉"이 아니라 "다다음 1분봉"입니다. 문서(2, 12, 14행)가 말하는 "다음 캔들 예측"과 실제 동작이 어긋나는 구조적 버그입니다.
2. **피처에 코인 자체 지표만 존재, 외부 맥락 부재 (41행 `FEATURE_COLS`)**: ret/vol_chg/rsi/macd/bb_pctb 모두 해당 코인 단독 OHLCV에서만 파생됩니다. 호가 스프레드(유동성 정보)나 BTC 등 기준 코인과의 상대강도/상관관계가 없어, 특히 알트코인에서 BTC 동조화로 인한 방향성을 놓칠 수 있습니다.
3. **파인튜닝 후 성능 악화 시에도 무조건 덮어씀 (168~170행)**: `val_acc`를 계산은 하지만 저장 여부 판단에 전혀 쓰이지 않습니다. 파인튜닝이 오히려 기존 모델보다 나빠져도 `existing_path`를 덮어쓰고 그대로 운영에 반영됩니다.
4. **SEQ_LEN(60)과 모델 크기(hidden=32, 1 layer)는 적절**: 30일치 1분봉이면 전처리 후에도 수만 개 샘플이 남고, 파라미터 수가 매우 작은(~5천대) 모델이라 이 정도 데이터량에서 과적합 소지는 낮습니다. 재학습 주기(1일)+학습기간(30일) 조합도 1분봉 방향성 예측 과제에 무리 없는 선택입니다.

## 구체적 제안
- **lstm_model.py 76~81행**: 루프를 `for i in range(seq_len - 1, n - 1):`로 바꾸고 `xs.append(arr[i - seq_len + 1 : i + 1])`(윈도우 끝이 `i`가 되도록), 라벨은 그대로 `close[i+1]` vs `close[i]` 유지. 이렇게 하면 윈도우 끝(`i`)과 예측 대상(`i→i+1`)이 연속되어 추론부(216행, `feat[-seq_len:]`)와 정의가 일치합니다. 수정 후 기존 `.pt` 가중치는 의미가 달라지므로 폐기하고 재학습 필요.
- **41행 `FEATURE_COLS`에 상대강도 피처 추가**: `build_features`에 기준 코인(BTC) df를 선택적 인자로 받아 `coin_ret - btc_ret` 컬럼을 추가하는 방식 검토.
- **168~170행에 회귀 방지 로직 추가**: 직전 학습의 `val_accuracy`를 JSON으로 같이 저장해두고, 새 `val_acc`가 이전보다 예: 3~5%p 이상 나쁘면 저장을 skip하고 결과에 `"regressed": True` 플래그 추가.

## 리스크/트레이드오프
- 인덱싱 수정은 기존 저장된 모델 가중치와 호환되지만 의미가 달라지므로 재학습이 필요하며, 수정 직후에는 성능 벤치마크를 다시 확인해야 합니다.
- 상대강도 피처 추가 시 입력 차원 증가로 학습/추론 비용이 소폭 늘고, 코인 간 데이터 정렬/결측 처리 로직이 추가로 필요합니다.
- 회귀 방지 로직은 val_accuracy의 자연스러운 날짜별 변동을 과도하게 "저장 skip"으로 처리하면 모델이 오래 갱신되지 않을 수 있어 임계값 튜닝이 필요합니다.
- 이 버그(1틱 어긋남)가 실제 운영 중 손익/정확도에 얼마나 영향을 줬는지는 실거래 로그와 학습 기록(실제 val_accuracy 추이, 신호별 성과)을 봐야 판단 가능 — 코드만으로는 영향의 크기를 알 수 없습니다.
