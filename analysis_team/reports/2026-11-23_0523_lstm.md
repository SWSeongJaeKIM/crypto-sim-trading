## 한줄 요약
피처/모델 구조와 파인튠 안전장치는 이미 여러 차례 리뷰를 거쳐 상당히 잘 다져져 있고, 남은 개선 여지는 "코인별 변동성 차이를 반영하지 않는 전역 라벨링 임계값"과 "알트코인에 BTC 동조화 신호가 피처로 안 들어감" 두 가지로 좁혀진다.

## 발견한 점 (우선순위 순)

1. **NEUTRAL_BAND(0.0005)이 6개 코인 전부에 동일한 절대 수익률 기준** — `lstm_model.py:50`에서 정의되고 `build_dataset()`(`lstm_model.py:126-131`)에서 `abs(next_ret) < NEUTRAL_BAND`로 라벨 제외 여부를 정함. BTC처럼 1분당 변동이 작은 코인과 DOGE/SOL처럼 변동이 큰 코인(`portfolio.py:46`의 `COINS = ["BTC","ETH","XRP","SOL","DOGE","ADA"]`)에 같은 0.05% 기준을 쓰면, 저변동 코인은 과도하게 많은 샘플이 "노이즈"로 걸러지고 고변동 코인은 거의 안 걸러지는 비대칭이 생긴다. 반면 매매 임계값(PROB_BUY_MIN/MAX, 확률 스케일)은 코인별 모델이 각자 학습 중 흡수하므로 이 문제에서 자유롭다.

2. **FEATURE_COLS(`lstm_model.py:84`)가 해당 코인 자기 자신의 가격/볼륨 지표로만 구성** — ETH/XRP/SOL/DOGE/ADA 5개 알트코인은 1분 단위에서도 BTC 움직임에 상당히 동조화하는 경향이 있는데, 이 정보가 피처에 전혀 없다. 저장소에 오더북/스프레드 데이터 수집 경로 자체가 없어(data_fetcher는 캔들만 수집) 호가 스프레드 피처 추가는 이 파일 범위를 넘는 큰 작업이지만, BTC 캔들은 이미 다른 코인들과 같은 파이프라인으로 수집되고 있어 추가 난이도가 낮다.

3. **SEQ_LEN=60 / LSTMClassifier(hidden=32, 1층) 구조, 그리고 파인튠 방식 자체는 적절** — 코인당 샘플 수(90일치 ≈ 13만개, `lstm_model.py:42` 주석)에 비해 모델이 작아 보일 수 있으나, 1분봉 방향 예측은 본질적으로 거의 랜덤워크에 가까운 과제라 용량을 키운다고 실제 신호가 늘지는 않고 과적합 위험만 커진다. 실측 val_accuracy가 54~62%에 머무는 점(주석, `lstm_model.py:52-59`)도 이와 부합. 파인튠 lr/3, 확신구간 기준 롤백 안전장치, finetune_chain_length 기반 주기적 전체 재학습(`main_loop.py:106, 779-785`)까지 이미 설계돼 있어 추가 변경이 필요하다고 보지 않는다.

## 구체적 제안

- `lstm_model.py:50`의 `NEUTRAL_BAND = 0.0005`를 코인 상대적 기준으로 교체. 예: `NEUTRAL_BAND_STD_MULT = 0.3` 상수를 추가하고, `build_dataset()`(111-135행)에서 각 시점 i까지의 최근 N분(예: 1440분) `ret`의 롤링 표준편차 `local_vol = feat["ret"].rolling(1440).std()`를 구해 128행의 비교를 `abs(next_ret) < NEUTRAL_BAND_STD_MULT * local_vol[i]`로 바꾼다. 초반 롤링 윈도우가 부족한 구간은 기존 고정값 0.0005로 폴백.
- `lstm_model.py:84`의 `FEATURE_COLS`에 `"btc_ret"`을 추가하고, `build_features()`(88-108행)가 해당 코인 df 외에 BTC df(또는 BTC의 `ret` 시리즈)를 추가 인자로 받아 open_time 기준으로 merge해 넣도록 수정. BTC 자신을 학습할 때는 자기 자신이므로 0으로 채우거나 피처에서 제외. `build_dataset`/`train_model`/`predict_proba`/`LSTMStrategy` 호출 체인(및 `main_loop.py`의 호출부)도 BTC df를 함께 넘기도록 수정 필요.

## 리스크/트레이드오프

- 롤링 변동성 기반 NEUTRAL_BAND은 변동성 자체가 추정 노이즈를 가지므로, 특히 거래량이 뜸한 시간대에는 라벨링이 오히려 불안정해질 수 있다 — 적용 전후 라벨 수/분포를 비교해 과도하게 줄거나 늘지 않는지 확인 필요.
- BTC 상관 피처 추가는 메인 루프의 데이터 전달 구조를 바꿔야 해서(각 코인 학습/추론 시 BTC df도 함께 로드) 코드 변경 범위가 이 파일을 넘어선다. 또한 모델이 "BTC 따라가기"에만 의존하게 되면, BTC-알트 탈동조화 구간에서 오히려 예측력이 떨어질 수 있다.
- 실제로 이 변경들이 수익성(손익)을 개선하는지는 운영 데이터(실거래 손익, val_accuracy 추이)를 봐야 판단 가능 — 이 리뷰에서는 코드 구조상의 개연성만 확인했다.
